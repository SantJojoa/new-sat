Detección de Conflictos en Salidas

Módulo: salidas.service.ts  ·  Función: checkConflicts()  ·  Generado:

1 ¿Qué es un conflicto?

Un conflicto ocurre cuando dos o más salidas activas comparten al menos un recurso (municipio, IPS+actor, entidad, EAPB+actor, organización o IDSN) dentro del mismo rango de fechas y en una jornada compatible.

Condición general: Los tres ejes deben cumplirse simultáneamente para que exista conflicto:
Solapamiento temporal AND Estado activo AND Recurso compartido.

2 Los tres ejes de detección

Eje 1 · Solapamiento temporal

Algoritmo clásico de intersección de intervalos:

fecha_inicio ≤ fin_nueva AND fecha_final ≥ inicio_nueva

Detecta cruces parciales, totales y contenidos.

Eje 2 · Estado activo

Solo participan en la evaluación salidas en:

  • pendiente
  • aprobada

Rechazadas, canceladas y entregadas no generan conflicto.

Eje 3 · Jornada compatible

Jornada nuevaConflicta conNo conflicta con
Día CompletoCualquier jornada (sin filtro)—
MañanaCompleta, MañanaTarde
TardeCompleta, TardeMañana
 
// Filtro de jornada en la query Prisma
const jornadaFilter = jornada === 'Completa'
    ? {}   // sin restricción → cualquier jornada genera conflicto
    : { OR: [{ jornada: 'Completa' }, { jornada: jornada }] };

3 Recursos compartidos

Basta con que uno de los seis tipos de recurso coincida para que haya conflicto. Se evalúan con un OR dentro del AND general.

RecursoCriterio de conflictoDistingue por actor
MunicipioMismo municipio_idNo
IPS Mismo ips_id AND mismo actor_id Sí — actor obligatorio
EntidadMismo entidad_idNo
EAPB Mismo eapb_id AND mismo actor_id Sí — actor obligatorio
OrganizaciónMismo organizacion_idNo
IDSNMismo idsn_idNo
IPS y EAPB distinguen por actor: se puede programar dos salidas a la misma IPS o EAPB en las mismas fechas siempre que visiten actores distintos. El conflicto solo se activa cuando coinciden ambos: la entidad y el actor. 
// Cada par (ips_id, actor_id) genera su propia condición
...ips_actores.map(item => ({
    salida_ips: { some: { ips_id: item.ips_id, actor_id: item.actor_id ?? null } }
})),

// Mismo patrón para EAPB
...eapb_actores.map(item => ({
    salida_eapb: { some: { eapb_id: item.eapb_id, actor_id: item.actor_id ?? null } }
})),

4 ¿Cuándo se ejecuta la verificación?

📝
Crear salida (POST /salidas) Se llama checkConflicts() antes de insertar. Si hay conflicto se lanza 409 y no se crea el registro.
↓
✏️
Editar salida (PATCH /salidas/:id) Solo se verifica si cambian fechas o recursos. Se excluye la propia salida del resultado (excludeId).
↓
🔍
Sin recursos → retorno temprano Si el resourceOr está vacío (sin municipios, IPS, etc.) la función retorna sin hacer query.
↓
⚡
Conflicto encontrado → HTTP 409 Se devuelve la lista detallada de salidas en conflicto: código, tema, fechas, jornada, área, solicitante y recursos.
